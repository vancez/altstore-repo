# AltStore 源管理器

*[English](README.md)*

用 Go 写的 AltStore / SideStore 源（source）实时生成服务。带一个适配桌面和手机的 Web 管理界面。

你只管填入仓库和一条正则，剩下的版本号、下载地址、上传时间、文件大小都由服务实时向该仓库的 release 接口要——默认是 GitHub，也可以按应用切换成 Forgejo 站点（如 starforgejo.dev）；应用名称、Bundle ID 这类站点不知道的信息在网页上填。

## 运行

```bash
go build -o bin/altstore-repo .
./bin/altstore-repo -addr :8080 -data ./data
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-addr` | `:8080` | 监听地址 |
| `-data` | `data` | 配置目录，状态存在 `config.json` |
| `-password` | 空 | 管理界面密码，也可用环境变量 `ALTSTORE_PASSWORD` |

打开 `http://localhost:8080/` 进入管理界面，订阅地址是 `http://localhost:8080/source.json`。

对外请求走的是 Go 默认的传输层，所以运行环境里设了 `HTTPS_PROXY` / `HTTP_PROXY` 就会生效——本机访问这些站点慢或者不通时可以用。

设了密码之后，除了订阅地址之外的所有路径都要 HTTP Basic 认证——手机订阅源必须能匿名拉取，管理界面则不应该对外开放。

## 添加一个应用

1. **仓库** 填 `owner/repo`，完整链接也认。粘链接时站点会跟着链接走并自动切换下面的**来源站点**；只填 `owner/repo` 就用下拉里选的那个。
2. **资源正则** 用来从 release 的附件里挑出要发布的那个文件。正则是对**文件名**做匹配，命中多个时取该 release 里的第一个。留空等同于 `(?i)\.ipa$`。用 `(?i)` 开头可以忽略大小写。
3. 点 **测试**，会立刻拉取 release 并列出每一个 release 命中了哪个文件、或者为什么被跳过。确认无误再保存。

版本号默认取 release 的 tag 并去掉开头的 `v`。tag 形如 `build-1234` 时，在「版本提取选项」里写一个带捕获组的正则，取第 1 组作为版本号。

**更新日志来自 release 自己的说明文字。** 每个版本都会带上它那个 release 的说明，写进 AltStore 的 `localizedDescription`，也就是手机上版本历史里显示的内容。release 没写说明的版本就没有日志，不会拿别的文字去凑。

## 来源站点

每个应用从**一个**站点读 release，在表单里逐个应用选：

| 来源站点 | 接口 | 说明 |
|---|---|---|
| GitHub | REST v3 | 默认 |
| Starforge（starforgejo.dev） | Forgejo / Gitea | 用来对接镜像仓库、或者不在 GitHub 上的构建 |

同一个源里可以混用，各应用互不影响，两个站点也不会共用同一份缓存。

Forgejo 站点上有几点不一样：

- **外链附件**：镜像过来的 release 通常不自己存文件，而是把附件链接到文件真正所在的地方（多半又是 GitHub）。这类附件**没有大小信息**（Forgejo 自己也拿不到），而且对方站点删了就失效，所以默认不参与匹配。要接受它们就在应用表单里勾上**包含外链附件**，测试面板里也就不会再显示为被跳过。
- **没有 ETag**：Forgejo 不支持条件请求，缓存时间一过就会完整读一遍 release 列表。缓存时间（「仓库设置」里，默认 300 秒）照常起作用，仍然是省流量的主要手段。
- **版本日期**取附件的 `created_at`。Forgejo 不返回 `updated_at`，而 GitHub 那边正是靠它来定版本日期的。
- **Token**：公开仓库不用填。私有仓库在「仓库设置」里填 Forgejo 的访问 Token，它只会发给 starforgejo.dev，不会发给 GitHub。

## 分组：一个源拆成多个订阅地址

「分组管理」里建分组，每个分组生成一个独立的订阅地址，只有分到该组的应用会出现在里面。应用表单里的「所属分组」下拉选一个，或者留空。

下拉里还有一项「新建分组…」，选中后保存应用时会顺带把分组建出来：分组名用应用名，标识为应用名把空格换成 `-`，副标题、描述、图标、色调沿用这个应用的信息，标识符留空。如果已有同名或同标识的分组，保存会失败。

应用名里一个 `a-z`、`0-9`、`-`、`_` 都没有时（比如纯中文名），推导不出标识，表单会要求手动填一个。

| 地址 | 内容 |
|---|---|
| `/source/all.json` | 全部应用 |
| `/source.json` | 同上，等价别名 |
| `/source/<分组标识>.json` | 只有该分组的应用 |

同一个分组标识被多个应用填了，它们就会合并进同一个 feed。没分组的应用只出现在 `all.json` 里。

分组标识只能是 `a-z`、`0-9`、`-`、`_`，长度不超过 64，且 `all` 是保留名。**创建后不能改**——应用是靠这个名字引用分组的。

分组的名称、标识符不填会自动派生：

- 名称 → `「源名称 · 分组标识」`
- 标识符 → `「源标识符.分组标识」`

其余外观字段（副标题、描述、图标、头图、网站、色调）不填就沿用源本身的设置。标识符如果手填，不能和源本身或其他分组重复——AltStore 靠标识符区分不同的源，重复了会把两个 feed 显示成同一个。

删掉一个分组，它下面的应用会变成未分组，仍然留在 `all.json` 里，应用本身不会被删。

## 行为细节

- **一律按名称排序**：应用按名称（没填名称就用仓库名）、分组按名称（没填就用标识），忽略大小写。网页列表、`config.json` 和生成的源都是同一个顺序，没有需要手动维护的排序。
- **每个应用的最新版本写两份**：一份在 `versions` 数组里（AltStore 读这个），一份平铺在应用上：`version`、`versionDate`、`size`、`downloadURL`（Feather 和旧版 AltStore 读这几个）。两处永远一致，手动覆盖版本时也一样。Feather 拿应用级的 `downloadURL` 当应用的身份标识，缺了它每次刷新都会把同一个应用当成新的。
- **版本日期**取**命中正则的那个附件自己的 `updated_at`**（不是 `published_at`，也不是同 release 里其他文件的时间）。GitHub 在补传附件时不会更新发布时刻，所以一个 2023 年发布、昨天才换过 ipa 的 release，真实时间应该是昨天。附件没带 `updated_at` 时退到它的 `created_at`（Forgejo 站点只有这个时间）。这个日期同时是版本排序依据。
- 正则测试面板里，**没有命中任何文件的 release 也会显示一个日期**，那是该 release 里最新的附件时间，仅用于辨认，不会进入生成的源。
- **更新日志就是 release 自己的说明文字**，每个版本一条，原样输出（Markdown 一并保留）。release 说明为空的版本就没有日志，而不是拿应用描述顶上。正则测试面板会在命中的文件下面显示该 release 说明的开头一段。
- **预发布版本**默认排除，可在「版本提取选项」里勾选包含。
- **草稿 release** 永远跳过。
- **同版本号去重**，保留最新的那个。
- **订阅地址只输出至少有一个可用版本的应用**。启用但一个版本都没匹配到的应用不会出现——否则手机上会显示成一个装不了的坏条目。
- **GitHub 限流**：不带 Token 是 60 次/小时。服务和 GitHub 之间有一层带 ETag 的缓存，缓存时间在「仓库设置」里调，默认 300 秒。缓存过期时会先发条件请求，304 不计费。额度真的用尽时会继续用过期缓存，而不是让源变空。
- **私有仓库**需要在「仓库设置」里填 Token：GitHub 只需要 `repo` 只读权限，Forgejo 的 Token 对公开仓库不需要任何权限。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/source.json` | 全部应用，公开，带 CORS |
| `GET` | `/source/all.json` | 同上 |
| `GET` | `/source/<分组>.json` | 单个分组 |
| `GET` | `/` | 管理界面 |
| `GET` `PUT` | `/api/config` | 源的元信息、各个站点的 Token、缓存时间 |
| `GET` `POST` | `/api/groups` | 分组列表（含各分组应用数）/ 新建 |
| `PUT` `DELETE` | `/api/groups/{slug}` | 修改 / 删除 |
| `GET` `POST` | `/api/apps` | 应用列表 / 新增 |
| `PUT` `DELETE` | `/api/apps/{id}` | 修改 / 删除 |
| `GET` | `/api/apps/{id}/versions` | 某个应用的解析结果，`?force=1` 跳过缓存 |
| `POST` | `/api/resolve` | 干跑，正则测试用的就是它 |

错误消息是双语的：请求带 `Accept-Language: zh-CN` 返回中文，其他或不带则返回英文。

## 界面语言

管理界面提供英文和中文。**默认英文**，顶部的切换器会记住你的选择；`?lang=zh` 或 `?lang=en` 可以生成指向特定语言的链接。

翻译分别在 `web/i18n.js`（界面）和 `i18n.go`（后端消息）。任何未翻译的条目都会回退到英文。

## 配置

状态全在 `data/config.json`，纯 JSON，可以直接编辑。写入用的是「先写临时文件再改名」，中途崩溃不会留下半个文件。

管理界面里的 Token（GitHub 和 Starforge）都是明文存的，每个应用从哪个站点读记在 `repoType` 里：`github`（不填即此）或 `starforge`。这个 id 指的是站点本身而不是域名，站点换域名不会让已有配置失效。这个服务是给你自己用的，别把 `data/` 提交到公开仓库。
